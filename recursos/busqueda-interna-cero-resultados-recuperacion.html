Cómo diseñar una búsqueda interna que ayude cuando no hay resultados

Una búsqueda interna también debe funcionar cuando no encuentra nada. Si devuelve una pantalla vacía, la persona no sabe si escribió mal, si un filtro oculta la respuesta o si el sistema falló. Diseñar esos estados permite continuar sin convertir cada consulta difícil en una solicitud de ayuda.

Define qué contenido puede encontrar el buscador

Enumera las fuentes incluidas: servicios, artículos, preguntas frecuentes o productos. Comunica ese alcance cerca del campo si puede confundirse con una búsqueda general. Separa el contenido público de información que requiera acceso; encontrar una coincidencia no debe otorgar permiso para verla.

Proponemos preparar un conjunto pequeño de consultas reales, sin datos personales: nombres de servicios, palabras cotidianas y expresiones ambiguas. Define el resultado esperado de cada una antes de ajustar el buscador. Esto permite evaluar si mejora la tarea, en lugar de celebrar únicamente que devuelve más enlaces.

Distingue resultados, ausencia y error técnico

Usa mensajes diferentes para “no encontramos coincidencias” y “no pudimos completar la búsqueda”. En el primer caso muestra la consulta y los filtros activos. En el segundo conserva lo escrito y ofrece reintentar. Decir que no existe contenido cuando el servidor falló lleva a una conclusión incorrecta.

La explicación de WCAG 4.1.3 de W3C incluye mensajes como el número de resultados o la ausencia de coincidencias cuando la página se actualiza sin cambiar el foco. Estos estados deben poder comunicarse a las tecnologías de asistencia. La lista de resultados no es, por sí misma, el mensaje de estado.

Ejemplo hipotético: “mantenimiento” con un filtro antiguo

Un visitante ficticio busca mantenimiento dentro de los artículos, pero había dejado activo el filtro “casos”. El sistema informa que no hay coincidencias en esa selección y ofrece quitar el filtro. Al hacerlo aparecen guías relacionadas, con títulos que explican su utilidad.

Otra búsqueda usa una expresión que el sitio todavía no cubre. El equipo no inventa resultados ni asegura ofrecer ese servicio. Propone explorar categorías o consultar al equipo, y registra de forma agregada la necesidad editorial. Las alternativas se presentan como sugerencias, claramente separadas de las coincidencias originales.

Checklist de estados y recuperación

  • Prueba una búsqueda habitual y otra sin coincidencias.
  • Combina consulta y filtros, y comprueba cómo se limpian.
  • Simula un fallo técnico y verifica que no aparezca como cero resultados.
  • Revisa con teclado el campo, el envío y las opciones de recuperación.
  • Comprueba el anuncio del estado con un lector de pantalla.
  • Repite con una consulta larga y otra con un error de escritura.

Si se sugieren correcciones, conserva visible el texto original y permite volver a él. Para búsquedas automáticas mientras se escribe, revisa la frecuencia de actualizaciones: anunciar cada pulsación puede interrumpir la lectura. El comportamiento debe probarse con el patrón que realmente se publique.

Usa las consultas para mejorar contenido y navegación

Revisa patrones de búsquedas sin respuesta y decide si falta contenido, una etiqueta comprensible o una conexión entre páginas. Evita guardar consultas completas indiscriminadamente, porque pueden incluir información personal. Complementa el trabajo con etiquetas y mensajes claros y con un recorrido móvil de contacto. Una búsqueda útil debe ofrecer una siguiente acción verificable, incluso cuando la respuesta sea que no encontró coincidencias.
