Cómo planear una migración web sin dejar páginas importantes atrás

Una migración de sitio necesita conservar el sentido de cada dirección, además de estrenar diseño. Antes de mover páginas, reúne un inventario y decide qué sucederá con cada una. La meta es que visitantes, enlaces y buscadores encuentren el contenido correcto, con excepciones visibles para el equipo.

Construye el inventario desde varias fuentes

Reúne URLs del gestor, sitemap, navegación, analítica y páginas conocidas por el equipo comercial. Incluye recursos enlazados desde campañas y documentos. Una página con pocas visitas puede seguir siendo el destino de un presupuesto o una guía enviada a clientes.

Como plantilla de trabajo, usa estas columnas: URL anterior, propósito, destino previsto, decisión, responsable y prueba. Marca las páginas críticas para atención y ventas. No cierres el inventario únicamente porque una herramienta terminó de rastrear: pregunta qué enlaces se utilizan fuera de la navegación habitual.

Decide qué se conserva, combina o retira

Cada dirección necesita una decisión editorial. Si el contenido se mueve, señala su equivalente. Si se combina con otra página, revisa que el nuevo destino responda realmente a la necesidad anterior. Si desaparece sin sustituto, documenta la retirada para que el equipo no improvise durante el lanzamiento.

Google advierte en su guía de migraciones con cambio de URL que enviar muchas direcciones antiguas a una portada irrelevante puede tratarse como un error de tipo soft 404. El criterio operativo es mantener correspondencias útiles, no esconder todas las ausencias detrás de la página inicial.

Prepara redirecciones y señales coherentes

La guía de Google recomienda redirecciones permanentes de servidor para las URLs movidas y actualizar las señales del nuevo sitio. Mantén las redirecciones al menos un año, y considera conservarlas más tiempo para usuarios y enlaces antiguos.

Verifica que el destino final coincide con el mapa aprobado. Revisa canonical, enlaces internos y sitemap para que no sigan apuntando a la versión retirada. Evita cadenas creadas por cambios sucesivos: prueba una dirección histórica y observa a dónde termina llegando. Una canonical no reemplaza una redirección para quien abre un enlace antiguo.

Ensaya el lanzamiento con casos incómodos

Prepara una lista de pruebas antes del cambio. Incluye una página conservada, una renombrada, dos contenidos combinados, una retirada y un archivo descargable. Verifica también las rutas con parámetros que realmente utiliza el negocio, sin asumir que cualquier parámetro merece preservarse.

  • Comprueba respuesta y contenido del destino, no solo que la URL abra.
  • Busca restricciones de pruebas que podrían permanecer en producción.
  • Ensaya formularios, navegación y descargas en la estructura nueva.
  • Define quién autoriza avanzar y quién puede restaurar la versión anterior.

Guarda la configuración previa y el mapa aplicado. Un plan de regreso debe considerar también las solicitudes recibidas después del cambio.

Ejemplo: dos páginas de un mismo servicio

Una empresa hipotética reúne “Diseño de páginas” y “Sitios corporativos” en una nueva página de desarrollo web. Antes de aprobar el destino, revisa que la nueva explicación conserve alcance, entregables y formas de contacto que necesitaban ambos públicos.

Si una de las páginas anteriores ofrecía mantenimiento y la nueva no lo menciona, la combinación todavía no está resuelta. El equipo puede preservar una página específica o incorporar un apartado pertinente. Elegir el destino por semejanza del nombre habría ocultado esa diferencia.

Haz seguimiento con un registro de incidencias

Después del lanzamiento, compara el inventario con las respuestas reales y revisa errores, consultas y páginas de entrada. Prioriza enlaces rotos que bloqueen tareas y registra cada ajuste. Espera posibles fluctuaciones de visibilidad durante el procesamiento; ninguna lista garantiza conservar posiciones. Cierra la migración técnica cuando los casos acordados funcionen, manteniendo separado el seguimiento de búsqueda que todavía requiera observación.

Para investigar una página del nuevo sitio que no aparece en búsquedas, sigue la revisión de indexación de una URL concreta.
