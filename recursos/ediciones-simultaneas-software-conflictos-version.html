Operación y software

Cómo evitar que dos personas sobrescriban el mismo registro

Dos personas pueden abrir la misma ficha, cambiar campos distintos y guardar con pocos segundos de diferencia. Si el sistema acepta todo sin comprobar la versión, una edición antigua puede borrar información reciente. Resolver esa situación exige una regla del servidor y una interfaz que ayude a decidir.

Reconoce qué cambios pueden entrar en conflicto

Haz una lista de registros compartidos y operaciones frecuentes. Corregir un teléfono y añadir una nota pueden ser compatibles; cambiar el estado de un pedido cancelado exige revisar las reglas del proceso. El conflicto depende tanto de los campos como del significado de la operación.

Define qué versión leyó el usuario al abrir la ficha. Al guardar, el servidor compara esa versión con la actual dentro de la operación que escribe. Comprobar primero y escribir después sin protección deja una ventana en la que otro proceso puede modificar el mismo registro.

Elige una estrategia con el equipo técnico

Una estrategia optimista rechaza o revisa la edición cuando la versión cambió. Los bloqueos pueden reservar acceso para determinadas operaciones, pero deben durar lo necesario. PostgreSQL documenta bloqueos de filas y advierte sobre esperas y bloqueos mutuos cuando varias transacciones compiten.

Evita mantener una transacción de base de datos abierta mientras una persona piensa frente al formulario. Para procesos largos, puede ser más apropiado guardar un borrador y volver a verificar al confirmar. La elección depende del volumen, la base de datos y las consecuencias de una colisión; requiere pruebas en la implementación real.

Ejemplo hipotético: una cotización compartida

Una asesora ficticia cambia la dirección de entrega mientras otro asesor ajusta cantidades. Al guardar la segunda edición, el sistema detecta que su versión quedó antigua. Presenta los campos modificados y conserva ambos borradores para decidir qué valores se aplican.

Una mezcla automática de campos sería peligrosa si la dirección determina gastos de entrega o condiciones de servicio. La interfaz debe mostrar las dependencias que obligan a recalcular. El usuario puede actualizar su propuesta sin perder lo escrito, y la confirmación final vuelve a validar el conjunto.

Prueba las colisiones de forma deliberada

  1. Abre el mismo registro en dos sesiones de prueba.
  2. Guarda cambios en el mismo campo y luego en campos distintos.
  3. Repite con una automatización que modifica el registro en paralelo.
  4. Comprueba qué ocurre al perder conexión y reenviar el guardado.
  5. Verifica que el historial permite identificar el valor final y su origen.

El mensaje de conflicto debe explicar cómo continuar. “Otro usuario actualizó esta ficha; revisa los cambios” es más útil que un error técnico sin salida. Evita revelar datos que la persona no tiene permiso de ver al mostrar la comparación.
