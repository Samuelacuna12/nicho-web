Agentes de IA

¿Agente de IA o automatización por reglas? Cómo elegir para tu proceso

No todo proceso repetitivo necesita un agente de IA. Si una empresa ya conoce los datos de entrada y la condición que determina cada paso, puede bastar una automatización por reglas. Cuando hay que interpretar mensajes variados, puede convenir añadir IA sin entregarle todas las decisiones. Esta guía ayuda a comparar esas opciones antes de pedir una propuesta, con criterios operativos y un ejercicio ficticio. No depende de una plataforma particular ni presupone que más autonomía produzca mejores resultados.

1. Describe la decisión que quieres resolver

Reemplaza «quiero un bot inteligente» por una frase comprobable: «cuando entre una solicitud, identificar su motivo, consultar el estado autorizado y dejarla con un responsable». Separa recibir información, interpretarla, decidir y ejecutar. Un mismo proceso puede necesitar soluciones distintas en cada etapa.

Para una muestra representativa, anota entrada, resultado correcto, fuente necesaria, excepción y consecuencia de equivocarse. Incluye casos incompletos, mensajes contradictorios y cambios posteriores, no solo las solicitudes fáciles. Usa datos ficticios o debidamente anonimizados para la evaluación inicial.

Si el equipo no coincide sobre el resultado correcto, primero aclara el procedimiento. Ni una regla ni un modelo resuelven por sí solos una política comercial indefinida. La matriz para priorizar procesos ayuda a elegir un alcance inicial manejable.

2. Usa reglas cuando la condición pueda escribirse y comprobarse

Una regla resulta adecuada cuando los campos son confiables y la respuesta está definida: asignar una solicitud según sede, validar que existe un identificador o detectar una fecha vencida. Documenta también qué ocurre cuando falta el dato. «No informado» no debe convertirse automáticamente en «no cumple».

Como ejemplo técnico, el nodo If de n8n permite comparar valores y combinar condiciones. Su nodo Switch permite varias rutas y configurar una salida para casos sin coincidencia. Estas funciones no garantizan que las reglas del negocio estén bien definidas.

Antes de programarlas, comprueba prioridades y solapamientos: ¿qué ocurre si dos condiciones se cumplen?, ¿se ejecuta una acción o varias?, ¿quién revisa la salida alternativa? Una automatización determinista también puede producir errores si recibe información vieja o una regla equivocada.

3. Añade IA cuando el problema sea interpretar, no inventar la política

Un mensaje como «lo necesito para el viernes, pero aún no sé cuál referencia sirve» no llega necesariamente en campos ordenados. La IA puede ayudar a identificar intención, resumir contexto o proponer preguntas. Eso no la autoriza a decidir una fecha de entrega que la operación no confirmó.

Anthropic distingue los flujos con caminos predefinidos de los agentes que eligen dinámicamente pasos y herramientas. La distinción sirve para conversar sobre arquitectura; no es una certificación de calidad ni obliga a usar un proveedor concreto.

Pregunta al implementador qué decisiones toma realmente el modelo. Si únicamente clasifica un mensaje antes de una secuencia fija, puede ser más claro describirlo como un flujo con una etapa de IA. Para un agente con mayor libertad, exige límites de acciones, fuentes consultables y condiciones de detención. El nombre comercial no sustituye ese mapa.

4. Ejemplo ficticio: solicitudes de una distribuidora

Ejemplo hipotético, no un cliente ni un resultado de NICHO: una distribuidora recibe tres tipos de solicitudes. Los formularios con número de pedido pueden consultar su estado mediante una regla. Los mensajes libres necesitan interpretación para distinguir una consulta de producto de una petición de cambio. Las excepciones comerciales requieren un asesor.

  • Ruta por reglas: identificador válido, consulta autorizada y respuesta basada en el estado registrado.
  • Ruta combinada: la IA propone el motivo del mensaje; una validación comprueba los campos antes de crear una tarea.
  • Ruta humana: falta información, hay contradicciones o la solicitud implica una excepción no autorizada.

Si alguien pide «cámbiame todo», el sistema no modifica un pedido interpretando libremente qué significa «todo». Pide precisión o deriva el caso. En cambio, una pregunta abierta sobre requisitos puede beneficiarse de una conversación guiada. El criterio cambia según la tarea, incluso dentro del mismo chat.

5. Compara opciones con la misma prueba y el mismo alcance

Prepara un conjunto de ejemplos y el resultado esperado antes de ver demostraciones. Prueba reglas, una solución combinada y, solo si hace falta, un agente con más autonomía. Usa las mismas entradas y registra no solo aciertos: cuenta correcciones, casos detenidos, acciones indebidas y minutos de supervisión.

Compara costo por tarea útil completada, no únicamente por mensaje respondido. Incluye consumo, revisión, mantenimiento y atención de excepciones. Una opción que responde rápido pero obliga a rehacer cada registro puede ser menos conveniente que otra con más pasos explícitos.

Define por separado fallos tolerables y fallos que bloquean el piloto. Una clasificación dudosa y una modificación no autorizada no tienen la misma consecuencia. La rúbrica de evaluación de agentes permite detallar el control; las metas deben acordarse según tu operación, no copiarse de una cifra universal.

6. Deja por escrito la elección y cuándo revisarla

La decisión de contratación debería caber en una ficha: problema, etapas por reglas, etapas con IA, fuentes, acciones permitidas, responsable de excepciones y evidencia para aprobar el piloto. Añade qué sucede si una integración falla o la información deja de estar disponible.

Empieza con un alcance reversible, observa los resultados y conserva una ruta manual. Para propuestas que permiten cambios en sistemas, revisa los permisos de un agente conectado al CRM. Cambiar la redacción de una respuesta y confirmar un pedido deben tratarse como capacidades diferentes.

Revisa la elección cuando cambien las entradas, políticas o herramientas, no solo porque aparezca un modelo nuevo. Si la necesidad se resuelve con condiciones claras, consulta automatización empresarial; si exige interpretación y uso controlado de información, evalúa el servicio de agentes de IA. El objetivo es una operación verificable, no añadir IA a cada paso.

El siguiente paso

Trae un proceso concreto, ejemplos anonimizados de entradas y las decisiones que hoy toma tu equipo. Podemos revisar qué partes conviene resolver con reglas, cuáles requieren interpretación y dónde debe conservarse la aprobación humana.
