Automatización de procesos

Qué proceso automatizar primero en una pyme: matriz de prioridad y riesgo

Ventas quiere automatizar seguimientos, administración pide reportes y operaciones necesita ordenar solicitudes. ¿Por dónde empezar? Antes de contratar, conviene comparar procesos concretos y comprobar cuáles están preparados para cambiar. Esta matriz ayuda a elegir un primer piloto sin dejar que el volumen de trabajo o una demostración atractiva oculten riesgos importantes.

1. Describe tareas comparables, no departamentos

«Automatizar ventas» no permite estimar dificultades ni comprobar una entrega. «Crear una tarea interna cuando una solicitud completa entra al CRM» sí delimita un recorrido. Para cada candidato escribe disparador, datos de entrada, regla, resultado esperado, excepción habitual y responsable. Empieza con tres candidatos, no con toda la empresa.

Revisa ejemplos recientes con quien realiza el trabajo. Anota cuántos casos hubo en un periodo comparable, dónde se atascaron y qué correcciones necesitaron. Separa tiempo de trabajo de tiempo de espera: una solicitud detenida por falta de aprobación no se resuelve necesariamente conectando aplicaciones.

El resultado de este diagnóstico es una decisión de alcance. La evaluación económica viene después; puedes continuar con nuestra guía para calcular el ROI de una automatización cuando exista un candidato viable.

2. Aplica condiciones de descarte antes de sumar puntos

Deja fuera del primer piloto cualquier candidato con una de estas condiciones pendientes:

  • No hay una persona que pueda explicar y aprobar la regla del proceso.
  • Las entradas no permiten distinguir casos o identificar qué registro debe cambiar.
  • No se ha comprobado el acceso autorizado a los sistemas necesarios.
  • Un error puede producir una acción difícil de revertir y no existe revisión humana efectiva.
  • Nadie asumirá las excepciones ni podrá detener la ejecución.

Descartar aquí significa preparar mejor o reducir alcance, no abandonar para siempre. Si automatizar pagos resulta inadecuado como primer proyecto, preparar una lista de pagos para revisión puede ser otro candidato. Debe evaluarse por separado.

OWASP recomienda privilegios mínimos y validación de permisos en cada solicitud. Para el diagnóstico, pide la lista de operaciones realmente necesarias: consultar, crear, modificar o eliminar. Tener una contraseña no demuestra autorización suficiente para todas ellas.

3. Puntúa prioridad y preparación de cero a doce

Esta escala es un método editorial propuesto para ordenar una conversación; no es un estándar certificado ni predice resultados. Asigna de 0 a 3 en cuatro criterios y suma: P = frecuencia + fricción + claridad + preparación.

  • Frecuencia: 0 si no ocurrió en el periodo revisado; 1 si ocurre menos de una vez por semana; 2 si es semanal; 3 si es diaria.
  • Fricción observable: 0 sin problema registrado; 1 si exige copia manual sin correcciones; 2 si genera correcciones repetidas; 3 si bloquea el siguiente paso de forma recurrente.
  • Claridad de reglas: 0 si dependen de criterio no documentado; 1 con diferencias entre personas; 2 con regla acordada y excepciones pendientes; 3 con reglas y excepciones documentadas.
  • Preparación técnica: 0 sin ruta de acceso comprobada; 1 con datos por ordenar; 2 con datos utilizables y conexión pendiente de prueba; 3 con una prueba de lectura o escritura controlada superada.

Si coinciden varias descripciones, usa la que represente mejor los casos observados y registra por qué. No conviertas una suposición en un 3. Marca «pendiente» si falta evidencia; ese candidato todavía no entra al ranking.

La referencia de conectores de Microsoft distingue disponibilidad por producto, conectores premium y estado preliminar. Revisa la documentación de tu plataforma y la operación específica; que aparezca el nombre de una aplicación no demuestra que tu flujo completo esté cubierto.

4. Mantén el riesgo en una columna independiente

Suma tres criterios de 0 a 2 para obtener R, entre 0 y 6. Evalúa el alcance propuesto con sus controles, no una versión ideal que todavía no existe.

  • Consecuencia: 0 para una salida interna sin compromiso externo; 1 para un cambio operativo corregible; 2 para dinero, compromisos con clientes o cambios críticos.
  • Recuperación: 0 si se deshace fácilmente y deja rastro; 1 si necesita intervención manual; 2 si es irreversible o no se ha comprobado cómo recuperarlo.
  • Exposición: 0 para datos no sensibles y acceso acotado; 1 para datos personales con permisos delimitados; 2 para información especialmente sensible o permisos amplios.

Como regla conservadora de este método, cualquier 2 obliga a rediseñar el piloto antes de elegirlo. Entre candidatos sin veto y con cada riesgo en 0 o 1, prioriza el menor R y luego el mayor P. Si empatan, elige el de menos dependencias externas. No restes riesgo a prioridad: una alta frecuencia no compensa una consecuencia inaceptable.

5. Ejemplo ficticio: tres candidatos, una decisión

Una distribuidora ficticia compara estas tareas. Las puntuaciones son supuestos didácticos, no mediciones de una empresa real:

  • Crear tareas internas desde solicitudes completas: P = 3 + 2 + 3 + 3 = 11; R = 0 + 0 + 1 = 1.
  • Preparar un reporte semanal sin datos personales: P = 2 + 1 + 3 + 2 = 8; R = 0 + 0 + 0 = 0.
  • Aprobar devoluciones y ejecutar reembolsos: P = 3 + 3 + 2 + 2 = 10; R = 2 + 1 + 1 = 4.

Con la regla propuesta, el reporte sería el primer piloto por su menor riesgo. La creación de tareas queda después, aunque tenga mayor prioridad operativa. Los reembolsos requieren rediseño: una nota alta no elimina el veto. Si el reporte aporta poco valor, la empresa puede decidir no contratar todavía; la matriz no obliga a automatizar.

6. Lleva una ficha de diagnóstico a la asesoría

Entrega al proveedor el proceso elegido, evidencia de las puntuaciones, herramientas implicadas, exclusiones y responsable. Acuerda pruebas con un caso normal, uno incompleto y uno repetido. Define qué resultado permite aceptar el piloto y qué error obliga a detenerlo.

Incluye quién revisará incidencias y cómo se vuelve al trabajo manual. Nuestra guía sobre fallos de integración y cola de revisión desarrolla esa parte operativa.

Para contrastar tus candidatos, puedes agendar una conversación con Nicho o visitar la página de contacto. Llevar ejemplos sin datos sensibles permite hablar de un alcance concreto antes de solicitar una propuesta.
